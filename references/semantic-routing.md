# 语义路由与无门禁规则

## 目标

用户只表达“想处理什么”和“处理到哪里”。系统负责从上下文、SRT、已有方案、场景文件和输出物中解析范围，并内部维护场次编号、阶段状态及质检证据。

## 解析顺序

1. 判断意图：分析、修改、生成、渲染或导出。
2. 判断对象：SRT、某一场、多个连续场次、动画方案、已生成内容或最终视频。
3. 判断范围：当前、开头、上一场、下一段、结尾、时间区间、字幕区间、文件或内容描述。
4. 用当前项目中的真实文件和对话上下文消歧。
5. 唯一匹配则执行；多项同等可信才提问；零匹配则报告具体缺口。

内部可使用 `S01`、`S02` 等稳定编号，但必须由场景顺序自动生成和解析。用户没有义务知道这些编号。

## 什么时候不能提问

- 用户已经给出唯一文件、唯一时间段或唯一上下文对象。
- “当前场”“继续下一段”等表达可从刚完成的产物唯一推断。
- 用户已经明确要求修改、生成或渲染，只是没有使用预设句式。
- 内部质检可以自行完成。

## 什么时候必须停下

- 同一句话能指向多个真实对象，且选择会产生明显不同的结果。
- 输入缺失、损坏或不可读，无法构建可信结果。
- 需要用户选择会改变内容含义、视觉方向或交付格式的方案。
- 所需运行环境或依赖不存在，且没有安全替代方案。

提问只问当前无法自行确定的一件事，并给出已发现的具体候选。

## 门禁被替换后的效果

旧式流程把编号、状态或凭据当作用户通行证。新流程保留内部状态机与质检，但它们只用于恢复、定位和验证：

- 用户侧：自然语言直接驱动动作。
- 解析侧：通过项目事实解析目标，不通过固定短语放行。
- 执行侧：唯一目标立即进入对应阶段。
- 质检侧：失败时内部修复；无法修复才报告真正阻塞点。
- 交付侧：只交付已通过检查的文件和必要说明。

## 连续操作

完成一场后，“继续”“下一段”“处理后面这场”等指令，应以前一产物的时间边界和场景顺序解析。内部日志仍记录精确编号和输入输出关系，以便恢复，但不把这些字段变成后续命令格式。
